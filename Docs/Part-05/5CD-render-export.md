# 5C/D — GPU allocation and delivery safety (first slice)

Stacks on 5B; merge #50 before this PR. Do not remove effects, reduce shader samples or silently change export settings. Lazy per-slot motion-blur accumulators avoid allocating three full-size RGBA16Float targets on a single-sample workload (nominal savings 47.5 MiB at 1080p, 189.8 MiB at 4K, not measured physical footprint). Existing work/backdrop targets remain. Refuse mismatched target allocation rather than using stale size. Propagate required scene/accumulation/resolve encoding failure; invalidate speculative cache metadata on rejected submission and mark failed GPU execution for invalidation on next submission. Mask blit and mip failures must not publish a cache hit. Render benchmark, video export, still/GIF and cursor layer require successful GPU execution. Cancel and join detached audio prep before temporary file cleanup; fail explicit audio input or unreadable mix instead of silently dropping it. Cursor writer cancels on failure and checks cancellation before publish.

Remaining: actual M1 measurements, hardware encoder telemetry, event-driven writer readiness, ordered prefetch, full resource ownership/resize stress, multi-output transactional publication, audio streaming, and all end-to-end release proof. Existing compatibility render callback remains for callers not yet migrated. GPU failure invalidation cannot retroactively cancel a preview already submitted; test error paths on hardware.
