# Backend 04A — bounded reader initialization
Base 39d43046b4638768ef38e6b0f72cd774daf85575; Part 4 of approved Recordly backend plan. Existing ProjectFrameReader checks a locked cache, suspends to instantiate a reader, and then rechecks; simultaneous requests can allocate duplicate decoders before either publishes. Replace only admission with a per-consumer actor, one in-flight factory, same LRU capacity and independent preview/export states. Regression tests exercise 16 concurrent same-key requests, distinct-key serialization, capacity and failure recovery. Existing frame decode, cache bytes, PTS logic and Metal compositor are unchanged. No speculative remux/native alternate compositor: effect eligibility, color audit, global byte budget, long-program audio and moving-backdrop profiling remain open. Measure seek latency and memory on actual Mac before claiming end-to-end improvement.
